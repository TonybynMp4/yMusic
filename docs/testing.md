# Testing

- Unit tests for the `packages/core` queue and the zod parsers against recorded InnerTube fixtures, with no Tauri. In the app, `useBrowse` against a fake engine and the real Query client (which pages the cache keeps, what a refresh shows, and how a long playlist loads, retries and resumes), and `useSongYear`. `useRatings` renders through plain `renderHook`, as it uses no Query client: when `ratingOf` gets a new identity, a late answer for an account switched away from, and a refused rating going back. Hooks that need React render in jsdom through `renderWithQuery` (`src/testing.tsx`), which wraps Testing Library's `renderHook` in the app's Query client: the account's playlists, recent searches and YouTube Music search are tested this way, each file opting in with `// @vitest-environment jsdom`, mocking `./engine.ts` and clearing the client before each test. The account's playlists also have plain unit tests for the merge in `libraryPlaylists.ts`: where new playlists go, which deleted ones are hidden, and when a pending one stops being pending. `tsc` across the workspace.
- `cargo test` in `apps/desktop/src-tauri`. `tests/bindings.rs` fails when `packages/ipc/src/bindings.ts` no longer matches the Rust commands; `pnpm bindings` regenerates it.
- A few Rust tests compare against snapshots with [insta](https://insta.rs): the tags read from every library fixture, the scan report for a file lofty cannot read, and the JSON that `settings_get`, `settings_set`, `library_tracks` and `library_resolve` send to the frontend. The expected output is committed under `tests/snapshots/*.snap`, so a change to a tag, a field name or a default shows up as a diff of that file. Values that change between runs (track ids, absolute paths, the art cache, scan times) are redacted in the test. Snapshots are for large structured output; a single value is still an `assert_eq!`.
  - After a change that alters a snapshot, `cargo insta test` runs the tests and writes the new output next to the old as `.snap.new`, and `cargo insta review` shows each diff to accept or reject. A new snapshot test is written the same way. Read each diff before accepting it: accepting a wrong snapshot makes the bug the expected output. `cargo install cargo-insta` installs both commands.
  - Plain `cargo test` fails on a mismatch and, locally, also leaves the `.snap.new` to review. CI sets `INSTA_UPDATE=no`, so it only compares and fails on a missing or different snapshot without writing anything.
- Network tests are opt-in: `YMUSIC_NETWORK_TESTS=1 pnpm --filter @ymusic/youtube test`. They cover search, browse, radio, stream resolution, the requests mpv really makes, and the PO-token path (the frame's `frame.js` in jsdom, asserting 206 with a token and 403 without). When the player endpoint answers with its bot check, the stream tests skip instead of failing. YouTube asks that of many datacenter addresses, GitHub's runners among them, so the nightly run covers search, browse and radio, and stream resolution needs a run from a home connection.

## Dead code checks

- `pnpm knip` runs [knip](https://knip.dev) across the workspace and fails on unused files, exports and dependencies, and on imports a package doesn't declare. Its settings are in `knip.jsonc`. The Vite and Vitest plugins supply most entry points (`index.html`, test files), each package's `exports` adds the rest, and the config lists the workers and `scripts/*.mjs`. When a finding is a false positive, add it to an ignore list in `knip.jsonc` with a comment saying why. Exports in `components/ui` are ignored on purpose: shadcn components keep their full upstream API.
- `cargo machete` in `apps/desktop/src-tauri` fails on crates in `Cargo.toml` that no source file uses. It reads the source and doesn't build, so it takes seconds. A crate it can't see used (only through a macro, `build.rs` or a `cfg`) goes in `[package.metadata.cargo-machete] ignored` with a comment. Install it with `cargo binstall cargo-machete` or `cargo install cargo-machete`.

CI runs both next to the lint steps.
